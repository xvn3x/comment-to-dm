# Восстановление пропущенных комментариев — v0.8.3

Webhook остаётся основным способом получения комментария. Дополнительный фоновый процесс читает комментарии через официальный Instagram API и передаёт пропущенные события в ту же очередь.

## Что происходит

- В live-режиме сверка включена по умолчанию. В mock-режиме внешних запросов нет.
- Сначала проверяются выбранные в правилах публикации и публикации с недавней активностью; для правил «все публикации» дополнительно обходится весь доступный список, включая старые Reels.
- По умолчанию один проход использует не более 8 запросов, между проходами — не менее 180 секунд. При большом числе публикаций/комментариев полный обход занимает несколько проходов, а не обязательно три минуты.
- Комментарию даётся минимум 60 секунд на обычную доставку webhook.
- Используется первое подходящее активное правило. Сохраняются публичный ответ, Direct, кнопки, проверка подписки после добровольного postback и follow-up.
- При высоком использовании API или rate limit сверка замедляется. Пауза исходящей очереди также останавливает сверку.

## Защита от повторов и старой рассылки

При первом включении после обновления сохраняется начальная дата. Более ранние комментарии автоматически **не обрабатываются**. Перезапуск сохраняет эту дату и положение обхода. Переподключение аккаунта и изменение правила не запускают историческую рассылку.

Сверка и webhook сохраняют один и тот же ID комментария. Уникальность в PostgreSQL и общая транзакция постановки в очередь защищают от дублей, включая одновременное поступление. Это действует, пока техническое событие сохраняется в истории приложения (30 дней).

Существующий ответ под комментарием приводит к консервативному пропуску всей цепочки. Пропуск тоже сохраняется, поэтому поздний webhook не запускает её снова. Ответ может принадлежать другому человеку — в спорном случае приложение предпочитает не отправлять повторно.

Ручные Direct вне приложения нельзя достоверно исключить по отсутствию диалога в API. Поэтому эта функция не является инструментом безопасной массовой повторной обработки старой истории.

Первый private reply ограничен семью днями **от создания комментария**, а не от его обнаружения. Более старые комментарии не восстанавливаются; восстановленные задания получают исходный срок окончания. См. [описание Private Replies от Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-23eacf45-3728-4e41-bcc7-6d164959327c).

## Настройка

В `.env` на собственном сервере (не отправляйте этот файл в чат):

```env
COMMENT_RECOVERY_ENABLED=true
COMMENT_RECOVERY_INTERVAL_SECONDS=180
COMMENT_RECOVERY_REQUEST_BUDGET=8
```

Допустимый интервал — 60–3600 секунд, бюджет — 2–30 запросов за проход. Увеличение бюджета расходует больше лимита API и не отменяет ограничения Meta. Для отключения задайте `COMMENT_RECOVERY_ENABLED=false` и пересоздайте контейнер приложения с новой конфигурацией.

Прогресс хранится в таблице `comment_recovery_state`: начальная дата, курсор обхода, время последней проверки и код последней ошибки. Тексты входящих комментариев там не сохраняются. Курсоры не содержат токенов доступа. Сетевые ошибки и потеря лизы не уничтожают сохранённое положение обхода.

## Ограничения

Это резервный механизм, а не гарантия доставки: Meta может не отдавать комментарий и при чтении, отозвать доступ или ограничить API. Большой архив публикаций увеличивает задержку обхода. Проверяйте журнал, состояние подключения и подписки webhook; не отключайте webhook ради сверки.

Функция восстанавливает комментарии, но не пропущенные входящие Direct или ответы на Stories. Установленные self-hosted копии обновляются только по решению владельца:

```bash
sudo /opt/comment-to-dm/scripts/update-vps.sh v0.8.3
```

Обновление создаёт резервную копию. Старый тег `v0.8.2` остаётся прежним и этой функции не содержит.
