# Comment to DM

Self-hosted приложение для одного Instagram Professional Account: комментарий с ключевым словом → публичный ответ → личное сообщение с текстом и HTTPS-кнопкой.

Приложение работает на сервере владельца. Оно не отправляет токены, комментарии или статистику разработчику проекта и не просит пароль от Instagram. Для подключения используется собственное Meta-приложение владельца и официальный OAuth.

> Проект находится в ранней версии 0.1. Перед подключением важного аккаунта сначала проверьте сценарий в `META_MODE=mock`, затем на тестовой публикации. Использование официального API снижает риски, но не гарантирует отсутствие ограничений со стороны Meta.

## Возможности v0.1

- одна установка — один Instagram Professional Account;
- конкретный Post/Reel или все публикации;
- ключевые слова, точное совпадение или любой комментарий;
- до трёх вариантов публичного ответа;
- одно private reply в Direct;
- необязательная HTTPS-кнопка;
- защита от повторной отправки одному человеку для того же правила и публикации;
- долговечная очередь с повторами при временных ошибках Meta;
- журнал статусов на 30 дней без хранения текста комментариев;
- mock-режим для проверки без Instagram;
- зашифрованное хранение App Secret и access token.

## Быстрое развёртывание на VPS

Потребуются Linux VPS, Docker с Compose, публичный IP и домен или постоянный поддомен, направленный на этот IP. Порты 80 и 443 должны быть открыты.

```bash
git clone <repository-url> comment-to-dm
cd comment-to-dm
npm install
npm run generate:env -- comment.example.com
docker compose up -d --build
```

Команда генерации покажет пароль администратора один раз. Сохраните его в менеджере паролей. Caddy автоматически запросит HTTPS-сертификат после того, как DNS начнёт указывать на VPS.

Откройте `https://comment.example.com`, войдите с созданным паролем и перейдите к подключению Meta.

## Развёртывание на Railway

Для первой рабочей установки это рекомендуемый вариант. Caddy и `docker-compose.yml` на Railway не используются: платформа сама собирает `Dockerfile`, выдаёт HTTPS-адрес и связывает приложение с PostgreSQL.

1. Создайте новый Railway Project и добавьте PostgreSQL.
2. Добавьте сервис приложения из этого GitHub-репозитория.
3. В сервисе приложения задайте переменные:

```env
NODE_ENV=production
META_MODE=live
PUBLIC_BASE_URL=https://your-service.up.railway.app
ADMIN_PASSWORD=<long-random-password>
SESSION_SECRET=<at-least-32-random-characters>
ENCRYPTION_KEY=<32-random-bytes-in-base64>
META_WEBHOOK_VERIFY_TOKEN=<random-token>
META_GRAPH_VERSION=v25.0
```

4. Добавьте `DATABASE_URL` как reference на переменную PostgreSQL-сервиса.
5. В Public Networking нажмите Generate Domain, затем впишите полученный HTTPS-адрес в `PUBLIC_BASE_URL` и выполните redeploy.
6. Healthcheck `/health` и restart policy уже определены в `railway.toml`.

Оставьте одну реплику приложения: очередь встроена в основной процесс и рассчитана на один self-hosted инстанс.

## Настройка Meta

1. Создайте своё приложение в Meta for Developers и добавьте продукт Instagram API with Instagram Login.
2. Для теста в Development mode добавьте владельца Instagram-аккаунта в роли приложения и примите приглашение.
3. В админке Comment to DM откройте «Подключение Meta». Там показаны точные OAuth callback и webhook URL для этой установки.
4. Добавьте OAuth callback в настройки Business Login for Instagram.
5. Добавьте webhook URL в Meta Dashboard, укажите значение `META_WEBHOOK_VERIFY_TOKEN` из `.env` и подпишитесь на поле `comments`.
6. Укажите Data Deletion и Deauthorize callback URL, показанные в админке.
7. Вставьте App ID и App Secret в админке и нажмите «Сохранить и подключить».
8. Авторизуйте профессиональный Instagram-аккаунт на официальной странице Instagram.

Не вводите пароль Instagram в Comment to DM, `.env`, терминал или чужую форму. Пароль должен вводиться только на странице Meta/Instagram.

## Первая проверка

До реального подключения оставьте в `.env`:

```env
NODE_ENV=development
META_MODE=mock
PUBLIC_BASE_URL=http://localhost:3000
```

Создайте правило для слова `гайд` и используйте блок «Тестовый комментарий». После проверки переключите `NODE_ENV=production`, `META_MODE=live`, верните публичный HTTPS URL и пересоберите контейнер.

На реальном аккаунте начните с отдельной тестовой публикации и второго Instagram-аккаунта, который не является автором публикации.

## Локальная разработка

Запустите PostgreSQL и создайте локальный `.env`. Затем:

```bash
npm install
npm run dev
```

Интерфейс доступен на `http://localhost:5173`, API — на `http://localhost:3000`.

Полезные проверки:

```bash
npm test
npm run build
npm run lint
```

## Архитектура

- React/Vite — минимальная админка;
- Fastify/TypeScript — OAuth, API и webhooks;
- PostgreSQL — правила, очередь и технический журнал;
- один встроенный worker — последовательная обработка исходящих запросов;
- Caddy — HTTPS и reverse proxy;
- Docker Compose — воспроизводимое развёртывание.

Webhook подтверждается сразу после сохранения события в базе. Публичный и личный ответы выполняются через долговечную очередь. При HTTP 429 и временных ошибках Meta используется ограниченный повтор с задержкой; постоянные ошибки попадают в журнал.

## Приватность и безопасность

Проект не содержит телеметрии и внешних шрифтов. В рабочем режиме он обращается только к Meta API и URL, открываемым самим пользователем по кнопке. Подробности и модель угроз описаны в [SECURITY.md](./SECURITY.md).

Секреты не должны попадать в Git. Файл `.env` уже исключён через `.gitignore`.

## Ограничения

- Только официальный сценарий private reply после комментария; это не холодная рассылка.
- Первый private reply ограничивается правилами и временным окном Meta.
- Повторный комментарий того же человека под той же публикацией не запускает то же правило второй раз.
- Входящие Direct, Stories, Live, вложения, цепочки и несколько Instagram-аккаунтов пока не поддерживаются.
- Версия Graph API настраивается. Перед реальным запуском сверяйте её и разрешения с актуальной документацией Meta.
